# BMAD 工作流阶段参考

## 阶段定义

### Phase 1: 分析 (Analysis)

**目标**: 理解问题域，明确产品方向

**角色**: 业务分析师 (bmad-analyst)

**输入**: 用户的想法 / 业务需求

**产出**:
- `product-brief.md` — 产品简报
  - 问题陈述
  - 目标用户
  - 核心价值主张
  - 成功指标
  - 约束和假设

**进入下一阶段的条件**:
- [ ] 问题陈述清晰、可验证
- [ ] 目标用户已识别
- [ ] 至少定义了 3 个成功指标
- [ ] 用户已审阅并确认产品简报

---

### Phase 2: 规划 (Planning)

**目标**: 将产品愿景转化为可执行的需求

**角色**: 产品经理 (bmad-pm) + UX 设计师 (bmad-ux-designer)

**输入**: 产品简报

**产出**:
- `prd.md` — 产品需求文档
  - 功能需求 (FR)
  - 非功能需求 (NFR)
  - Epic 和 User Story 概览
  - 优先级排序 (MoSCoW / RICE)
- `ux-design.md` — UX 设计文档
  - 用户流程
  - 线框图描述
  - 组件规范
  - 可访问性考量

**进入下一阶段的条件**:
- [ ] 所有核心 Epic 已定义
- [ ] NFR 已明确（性能、安全、可扩展性）
- [ ] 用户流程完整覆盖核心功能
- [ ] 用户已审阅并确认 PRD

---

### Phase 3: 方案设计 (Solutioning)

**目标**: 设计技术方案，拆解可实施的工作单元

**角色**: 系统架构师 (bmad-architect) + Scrum Master (bmad-sm)

**输入**: PRD + UX 设计

**产出**:
- `architecture.md` — 系统架构文档
  - 技术栈选型
  - 系统组件图
  - 数据模型
  - API 规范
  - 部署架构
- `epics/*.md` — 拆解后的 Epic & Story 文件
  - 每个 Story 包含验收标准
  - Story Point 估算

**进入下一阶段的条件**:
- [ ] 技术栈已确定
- [ ] 所有 NFR 已映射到架构决策
- [ ] Story 已拆解到可实施粒度（≤8 点）
- [ ] 实施就绪检查通过

---

### Phase 4: 实施 (Implementation)

**目标**: 编写代码、测试、交付

**角色**: 开发者 (bmad-dev) + QA

**输入**: 架构文档 + Stories

**产出**:
- 可运行的代码
- 测试（单元 / 集成 / E2E）
- 代码审查记录

**完成条件**:
- [ ] 所有 Sprint Story 已实现
- [ ] 测试覆盖率 ≥ 80%
- [ ] 代码审查无阻塞问题
- [ ] 文档已更新

## 级别适配

| 级别 | Phase 1 | Phase 2 | Phase 3 | Phase 4 |
|---|---|---|---|---|
| L0 原子变更 | 跳过 | 跳过 | 跳过 | 直接实施 |
| L1 小功能 | 简化 | 简化 | 跳过 | 实施 |
| L2 中型项目 | 完整 | 完整 | 完整 | 完整 |
| L3 大型项目 | 详细 | 详细+评审 | 详细+评审 | 多冲刺 |
| L4 企业级 | 详细+合规 | 详细+评审 | 详细+评审+POC | 多冲刺+CI/CD |
